# HARE 容器·子畫布巢狀架構

HARE 有**兩種**表達卡片關係的方式，別混用：

| 方式 | 語意 | 怎麼做 | skill |
|---|---|---|---|
| **依賴線（edge）** | 「A 依賴 B／A 之後才 B」＝流向（DAG，左→右） | `add_edge` | `hare-card-layout` |
| **容器·子畫布（containment）** | 「B 是 A 的內部功能／A 由這些子卡組成」＝拆解 | `parentId` 巢狀 | **本 skill** |

> 口訣：**流向用線、組成用框。** 問「誰先誰後」→畫線；問「它裡面有什麼」→放進子畫布。

範例：`W2「前端內容」`是一個容器，子畫布放 `W1-2 控制框類別`、`W1-3 工作卡片`…每張都是前端的一塊功能；
`W1-3` 自己又是容器，子畫布放 `名稱/說明/程式/任務/邊緣色…`＝工作卡片的內部欄位。
後端則有 `後端內容(SBE)` 概念下的 `S1..S7` 層容器，各自子畫布放該層的功能卡（B 系列）。

---

## 1. 容器解剖（一張卡怎麼變成容器）

任何非 lane/scope 卡都能當容器。它的版面由上而下是：

```
┌─ 容器卡 ────────────────┐
│  標題列（label）          │  ← 高度 = childTop（由 ChildSpacer 量測回寫）
├─────────────────────────┤
│  子畫布（child zone）     │  ← 高度 = childZoneH（自動長高以容納子卡）
│   ┌─子卡A─┐              │
│   ├─子卡B─┤ 垂直堆疊      │
│   └─子卡C─┘              │
├─────────────────────────┤
│  任務區（tasks）— 被推到  │
│  子畫布之下、永不重疊      │
└─────────────────────────┘
```

- **`childTop`**：子畫布上緣（相對容器 y）。**前端量測後自動回寫**，agent 不用也不能預設。
- **`childZoneH`**：子畫布高度。**只增不減**——前端隨子卡 bounding 自動長高；要縮＝使用者拖容器下緣把手。
- **`minW`**：容器最小寬。子卡太寬時前端自動擴。
- 子卡：`parentId` 指向容器、`extent:"parent"`（限制在框內）、`position` 相對容器。

**關鍵**：`childTop/childZoneH/minW` 全是**前端渲染衍生值**，不進內容指紋、agent 無法經 MCP 設定。
你只負責「把子卡 parentId 掛對、給合理相對座標」，容器尺寸交給前端自動收斂（與瀏覽器「+卡片」同一套邏輯）。

## 2. Agent 建巢狀結構的安全套路（照做不踩雷）

**只用垂直堆疊放子卡**——這是瀏覽器 `+卡片` 的原生行為，前端 child-zone effect 專為它設計，最穩：

1. 先建容器：`add_card({ label, type:"note", num, x, y })`（頂層容器給絕對座標）。
2. 子卡逐張掛上：`add_card({ label, num:"<父num>-<n>", parentId:"<父>", x:16, y:64+n*90 })`
   - `x` 固定 **16**（左內邊留白；<0 或 <8 會被前端拉回）。
   - `y` 遞增堆疊（起始 ≥ **64**；前端會把整組平移對齊到量測出的 `childTop`）。
   - `num` 沿 **父卡編號-序號**慣例（如 `S3-2`、`W1-3-1`）。
   - **留 PADDING、勿緊貼**：子卡與容器邊緣要留白，不要貼齊。
     - 左：`x = 16`（≥16）；**列距 ≥ 90**（子卡間垂直留白，勿疊）；起始 `y ≥ 64`（避開標題列）。
     - 右／下留白交給前端（`minW = 子卡最右 + 16`、`childZoneH = 子卡最底 + 6`）；若要更寬鬆，
       把子卡整體往內縮（x 稍大、末卡別頂到底）。**寧可留白多，也不要子卡貼死容器框。**
3. **不要**自己算 `childTop`、不要塞 `minW/minH`（塞不進去，也會跟前端打架）——建完等前端收斂即可。
4. 型別：容器與子卡都用 `type:"note"`（決策/流程卡）或按內容；`chip` 需 parentId 且限技術範圍框。

### 反例（會亂）
- ❌ 子卡橫向散放又指望容器立刻長寬——初期 `extent:"parent"` 可能夾住、收斂慢。**先垂直堆疊**。
- ❌ 三層以上「大根容器裡塞多個並排子容器」一次灌完——並排子容器的自動長寬較不穩；
  **改用多個頂層層容器一列排開**（座標你全控、無父層夾制），各自內部再垂直堆疊子卡。這就是 `S1..S7` 的作法。
- ❌ 用依賴線硬連出樹狀圖來冒充組成關係——那是 DAG 流向，語意不同（見 §0 口訣）。

## 3. 搬卡進出容器：`move_card`

改變歸屬用 `move_card`（不是 `update_card`——parentId/座標是節點級、不在 data）：

- **放進容器**（成為其內部功能）：`move_card({ card:"W1-9", parentId:"S3", x:16, y:420 })`
  → 設 `parentId`+`extent:parent`，座標相對新容器子畫布。
- **移出成頂層**：`move_card({ card:"X", parentId:null })`
  → 座標自動轉絕對（不跳位）、移除 parentId。
- **只挪位置**：`move_card({ card:"X", x, y })`（省略 parentId＝不改歸屬）。
- 內建防環：不能搬進自己的子孫、不能設自己為父。

實例：把誤置於 `W2 前端內容` 的 `W1-9(MCP)`、`W1-5(分析)` 併入後端 `S3/S7` 層——
`move_card` 一步到位，前端自動把它排進目標容器子畫布並長高容器。

## 4. 收尾驗證（沿鐵律「實跑觀察」）

1. `get_card <容器> fields:[position,childTop,childZoneH,minW]` 或直接讀資料檔，確認：
   容器 `childTop` 已量測、`minW/measured` 已長到容納子卡、子卡 `parentId` 正確。
2. 瀏覽器（port 5233）實開或截圖：容器框住所有子卡、子卡不溢出、任務區在子畫布下方不重疊。
3. 搬卡後確認舊容器不再含該卡、新容器已含（`nodes.filter(parentId===舊/新)`）。

> 一句話：**容器＝框、子卡＝內部功能；只管掛 parentId＋垂直堆疊 x:16，尺寸讓前端自己長。**
