# HARE 語意板生成準則

機械板（analyze_codebase）回答「檔案長怎樣、誰 import 誰」；語意板回答「系統是什麼做的、
怎麼運作、給人怎麼用」。語意板由 agent 自主建立：**事實來自機械工具，判斷來自 agent**。

## 共用鐵則（三種板型都適用）

1. **事實與判斷分離**：介面/依賴事實一律取自機械工具（`scan_interfaces`＝每檔 exports
   與 import 符號；`analyze_codebase` 板＝檔案結構），不憑印象手抄；分組、命名、取捨
   是 agent 的判斷，用使用者的語彙。
2. **獨立存放**：語意板自成一板，掛為所屬專案的**分頁**（create_project 的
   `group`＝專案群組、`page`＝分頁名）。機械板可重生、語意板不可被重生覆蓋。
3. **每卡有編號、有出處**：編號沿 HARE 慣例（頂層一字母、子孫遞增、G 保留）；卡片
   refs 指回實作（path；可精確到位置的補 HARE 註解＋uuid）。
4. **箭頭語意**（add_edge `arrow` 參數）：source→target 一律＝動線方向（排版分欄依此）。
   注入（import/依賴提供）＝`inject`；呼叫類型（往返）＝`both`；流程先後＝`flow`（預設）。
5. **排版**：依 skill `hare-card-layout`（分層左→右、河道分類、跨帶節點卡代理、
   批次用 layoutLayered）。
6. **驗證分工**：板上宣稱的事實（埠號、協定、元件關係）要能指出程式出處；
   status=real 只有實跑驗證過才准標。

## 板型一：模組介面圖

回答「每個模組對外提供什麼、誰注入了誰的什麼」。

- **卡片＝模組**（通常一檔一卡）：label＝模組名，`listing`＝exports 清單
  （取自 scan_interfaces，超過 12 項截斷加「… 其餘 N 項」），refs＝檔案路徑。
- **線＝實際注入的符號**：label＝符號名（多符號取最重要 1–3 個＋`×N`），`arrow:"inject"`。
  symbols 空（整包引入）→ label 用模組名。
- **分組＝功能域容器**：把同一職責的模組放同一容器（命名由 agent 判斷）；
  跨容器的線聚合成容器級一條。
- 取捨：只畫「被 ≥1 個其他模組注入」的介面關係；孤立模組列出但不強拉線。

## 板型二：系統架構圖

回答「執行起來有哪些元件、怎麼通訊」。單位是**執行期元件**，不是檔案。

- **卡片＝元件**：進程／服務／埠／資料儲存／排程／外部服務。desc 記機械事實：
  埠號、協定、啟動指令、資料檔位置——每一項都要有程式出處（refs 指到定義處）。
- **線＝執行期通訊**：請求-回應（呼叫類型）＝`arrow:"both"`，label 寫協定/介面名
  （如 `HTTP /api/...`、`stdio JSON-RPC`）；單向資料流（寫入、廣播、觸發）＝`arrow:"flow"`。
- **河道＝執行環境邊界**：以「誰在哪個進程/主機/宿主裡跑」分帶，動線左→右＝
  使用端→服務端→儲存端。
- 事實來源：入口檔（啟動什麼）、設定檔（埠/路徑）、`scan_interfaces`（模組掛在哪個
  入口下）——agent 讀碼確認後才畫。

## 板型三：功能架構圖

回答「使用者看到什麼、能做什麼」。單位是**功能**，命名用使用者的語彙。

- **分解層次**：頁面/畫面 → 區塊/面板 → 元件/控制 → 互動/手勢，容器逐層巢狀。
- 一個檔案可以拆成多張功能卡（同一 App 裡的多個面板各自成卡），refs＋HARE 指回
  該功能的實作位置。
- 線只畫「功能間的觸發/導航關係」，`arrow:"flow"`；同層並列不拉線。

## 建板流程（每次照做）

1. 跑機械工具取事實（scan_interfaces／讀機械板／讀關鍵程式）。
2. 決定板型與分組，先在心中或草稿排出容器樹與動線方向。
3. `create_project` 獨立板並掛進所屬專案的分頁（`group`＝專案群組、`page`＝分頁名，
   如「模組介面」「系統架構」），依 `hare-card-layout` 算座標批次建卡建線。
4. 回讀驗證（list_cards／瀏覽器 5233）：無重疊、編號齊、refs 可跳轉。
5. 種一張導引卡說明本板板型、資料來源與生成時間，狀態 wait＝待使用者驗收。
