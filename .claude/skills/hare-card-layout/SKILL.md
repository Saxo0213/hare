# HARE 卡片自動排版準則（Layered Layout）

HARE 是「依賴圖路線白板」。卡片座標不是隨便放的——它要表達**依賴方向**與**階段層級**。
本準則把業界標準的 **layered（Sugiyama）圖佈局**簡化成一組固定格線常數，讓 agent 用
`add_card` 的 `x`/`y` 參數（或事後 `update_card` 調整）就能排出整齊、可讀的版面。

> 核心口訣：**欄＝依賴深度（左→右流動），列＝同層並列（上→下堆疊），格線固定不亂飄。**
>
> **語意：「上游」＝入口（使用者查詢的起點），一律在最左；線段順著查詢動線由左向右。**
> 任務板：上游＝前置任務；程式分析板：上游＝入口模組（引用者），線＝引用者→被引用。
> 線段語意是「動線」，不是抽象的依賴方向——使用者從入口一條一條往下查。

---

## 1. 格線常數（勿隨意更動）

| 常數 | 值 | 說明 |
|---|---|---|
| `X0`（首欄左緣） | `60` | 第 0 層卡片的 x |
| `Y0`（首列上緣） | `60` | 第 0 列卡片的 y |
| `COL_PITCH`（欄距） | `460` | 相鄰兩層的 x 間距 |
| `CARD_W`（標準卡寬） | `360` | 由此得水平間隙 = 460−360 = **100px** |
| `ROW_PITCH`（列距） | `340` | 同一層相鄰兩列的 y 間距（適用一般高度卡片） |
| `ROW_PITCH_TALL`（高卡列距） | `560` | 前一張是「內容多」卡片時改用（見 §4） |

**座標公式**

```
x = X0 + layer * COL_PITCH        // layer = 依賴深度，見 §2
y = Y0 + rowOffset                 // rowOffset 為該層已佔用高度累加，見 §3
```

---

## 2. 決定「欄」（layer）＝依賴深度

一張卡的 `layer` = **從入口卡片到它的最長動線長度**（拓樸分層）：

1. 沒有任何 incoming edge（無前置）的卡片 → `layer = 0`（放最左欄）。
2. 其他卡片 `layer = max(所有上游卡片的 layer) + 1`。
3. edge 一律 **source 在左、target 在右**（source.layer < target.layer）。若新增連線後
   出現「右指左」，代表 target 該往右移一欄——用 `update_card` 把 target 及其下游整批右移。

實務簡化：路線圖有明確階段時，可直接用階段當 layer 基準（第一階段=0、往後遞增），
再依實際依賴微調。**先問「它的上一步是誰」，把它放在上一步的右邊一欄。**

> 例外卡（等待外部條件、低優先旁支）允許不嚴格分層，但仍要落在格線交點上，不可懸空亂放。

---

## 3. 決定「列」（row）＝同層並列，垂直不重疊

同一層可能有多張卡片，往下堆疊：

1. 該層第一張：`y = Y0`（= 60）。
2. 之後每一張：`y = 前一張的 y + 前一張佔用的列距`。
   - 前一張是**一般卡** → 加 `ROW_PITCH`（340）。
   - 前一張是**內容多卡**（見 §4）→ 加 `ROW_PITCH_TALL`（560）。
3. 目標：任何兩張卡的可視範圍**垂直至少留 40px 空隙**，水平（跨欄）自然有 100px 間隙。

放卡前先 `list_cards` 或 `get_card ... fields:[position]` 讀同層現有卡片的 y，取**最大 y**，
再往下加一個列距，即為新卡 y——避免疊在別人身上。

### 兩式可隨機擇一

上述堆疊為**甲式**（預設）。整板排版時可隨機改採**乙式・脊椎走廊**（使用者指定則從指定）：

- 先判定**主動線**（入口→終點的主鏈，通常＝使用者請求走的那條），這串卡全鎖同一 y
  （走廊，建議 `Y0 + ROW_PITCH`）——主路徑一眼走完，不上下蛇行。
- 其餘卡排走廊兩側，**上帶＝控制/橫切面**（認證、設定、快取），**下帶＝資料/非同步**
  （儲存、佇列、背景工）；旁支以垂直短線接回主鏈，不走對角線。
- 適配：有明確主動線的板（系統架構、請求鏈）乙式較易讀；無主鏈的純並列板用甲式。
- 乙式屬手動格線放卡；批次 `layoutLayered`（§9）仍走甲式邏輯。

---

## 4. 卡片高度會變，用「內容量」估列距

前端 `measured.height` 是渲染後才算的，agent 建立當下無從得知。用內容量估：

- **內容多卡**（任一成立）：`tasks` ≥ 4 條、或 `desc` 超過約 120 字、或型別為 `plan` 且兩者皆有。
  → 下一張用 `ROW_PITCH_TALL`（560）。
- 其餘一般卡 → `ROW_PITCH`（340）。

寧可高估留白，不可低估重疊。事後若使用者回報太擠，用 `update_card` 加大 y。

---

## 5. 泳道（lane）必須容納所有卡片

卡片不可超出泳道邊框，否則視覺破格。

- 放卡後計算最右卡右緣 `xMax = x + CARD_W`、最底卡下緣 `yMax = y + 估計高度`。
- 若 `xMax + 40 > laneX + laneW` 或 `yMax + 40 > laneY + laneH`，代表泳道要放大：
  更新 lane 的 `w`/`h`（及對應 `width`/`height`），右下各留 ≥ 40px 邊距。
- 每個專案自有泳道，同規則套用到各自的 lane。

---

## 6. 連線（edge）方向與端點

- 線段 source→target 一律＝**動線方向**：上游（入口側）→ 下游，對應左 → 右，
  排版分欄依此。用 `add_edge(source, target)`。
- **箭頭另表關係語意**（`arrow` 參數）——卡片順序表層次，箭頭表關係方向：
  - `flow`（預設）＝流程/任務先後：箭頭在終點（前置 → 後續）。
  - `inject`＝注入（import/依賴提供）：被引用者注入引用者，箭頭畫在**起點端、
    指回引用者**（markerStart + auto-start-reverse），不畫終點箭頭。
  - `both`＝呼叫類型（往返關係）：雙向箭頭。
- 想更整齊可指定 `handles`：一般用 `{source:"r", target:"l"}`（右出、左進），
  讓線水平穿越 100px 間隙、減少交叉。
- 同一 target 有多個上游時，讓上游卡片在**垂直方向靠攏排列**，多條線平行進入，避免打結。

---

## 7. Agent 建卡標準流程（每次照做）

1. **定位**：這張卡的上一步是誰？→ 決定 `layer`（§2）。
2. **算 x**：`x = 60 + layer * 460`。
3. **選列**：甲式取同層 `maxY + 列距`（§3、§4），該層無卡則 `y = 60`；
   乙式主動線卡鎖走廊 y、旁支依上帶/下帶讓開（§3 兩式）。
4. `add_card({ label, type, status, desc, tasks, x, y, ... })`。
5. 有連線就 `add_edge`（左→右，`handles:{source:"r",target:"l"}`）。
6. **檢查泳道**（§5）：超框就放大 lane。
7. **回讀驗證**：`get_card <新卡> fields:[position]` 確認座標如預期，並在瀏覽器（port 5233）
   或 SSE 觀察版面無重疊——符合鐵律「不造假、實跑觀察」。

---

## 8. 反例（不要這樣）

- ❌ 用 `add_card` 的預設座標連續丟多張 → 全疊在同一點。
- ❌ x 不落在 `X0 + n×COL_PITCH` 格線上 → 欄位參差。
- ❌ 線段由右指左 → 讀者無法用方向判斷先後。
- ❌ 卡片凸出泳道外 → 版面破格。

> 一句話：**先想清楚它在動線的第幾層第幾列，算好格線座標再 add_card，別讓前端替你收爛攤。**

---

## 9. 批次自動排版（`lib/layout.mjs` layoutLayered）

§1–§8 是「一張一張放」的手動格線；**大量卡片**（analyze_codebase 生成板、批次匯入、
「幫我整理版面」、工具列「重排」鈕）改用 `layoutLayered(items, edges, opts)`
（HARE 5u91y4ma；React Flow 技術細節見 skill `react-flow` 的 references/layouting.md）。
內部分工：rank 分層＋barycenter 減交叉＝dagre；估尺寸與連通元件切分/打包＝自製。四段原則：

1. **先定尺寸再排版**：每個 item 必須帶估算 `w`/`h`——寧可高估留白，不可低估重疊。
   容器卡高度＝表頭＋子卡堆疊 bottom-up 累加。
2. **rank 分層**＝最長路徑（同 §2 的 layer；環→走訪保護回退 0）。
   邊一律以「動線方向」（上游→下游）餵入，source 排左欄。
3. **barycenter 減交叉**：同欄卡片依「鄰居平均序位」重排，交替方向掃數輪。
4. **連通元件切分＋打包**：互不相連的群各自排版，再依面積 shelf packing 成
   接近 16:9 的網格——不切分時無依賴的節點會全落 rank 0，疊成一條長欄。

參數：`ranksep`（欄距）預設 140、`nodesep`（同欄距）70、`compsep`（元件距）120；
容器內排版用較小間距（ranksep 70、nodesep 26）。座標一律輸出**左上角**
（dagre 回中心點，包裝層已轉換）。

### 生成板鐵則（analyze_codebase 已內建，手工批次也要遵守）

- **頂層要分河道**：分類只用機械事實——程式主體依「容器級依賴 rank」分帶
  （入口層→中間層→基礎層，左→右），資源、外部依賴各自成帶；一帶一 lane 背景、
  全帶等高（縮到最遠看到的就是分類帶標題）。不得用名稱字典猜語意分類。
- **跨河道連線取捨**：相鄰河道（跨 ≤1 帶）主體相連（容器級聚合線照畫）；
  跨 ≥2 帶改**節點卡代理**（off-page connector）——來源主體右側就地放代理卡
  （`data.proxyFor`＝本尊 id，label＝`⇒ 本尊編號 名稱`），線只連到代理卡，
  長線不橫穿版面；前端點代理卡＝跳到本尊。
- **跨群組的線要聚合**：兩個容器間的多條卡片級連線合併成一條「×N」容器級線，
  否則滿版蜘蛛網（同容器內的線保留）。
- **容器內也要分層**：子卡之間有連線時，一樣餵 layoutLayered；無連線才用多欄網格
  （>8 張換欄，欄寬 264——長直欄是可讀性殺手）。
- **排版只動卡片，不彎折線段**：線一律走使用者選的線型自然路由；卡壓線、線交叉
  以「卡片位置、欄距/列距、同欄排序」處理。同欄排成一直線**不是硬約束**——
  跨欄長線壓到中間欄卡片時，被壓卡片以「向右平移為主、垂直微調為輔」讓開，
  且右移吃掉的欄間走廊由後續欄整欄右移連鎖補回、一路檢討到最右欄
  （layoutLayered 內建避線位移＋位移連鎖；避線查的線形＝定案端點側——facing 一段、
  corner L 兩段——含轉角淨空，定案側隨 `sides` 回傳、前端畫線直接沿用）。
- **每張卡都要有編號**（頂層容器一字母、子孫依序遞增；G 避讓——歷史導入說明卡用過）
  ——編號是 HARE 的溝通索引，也是縮放導覽層的分類依據。
- **描述程式的卡建立當下就帶 refs**：`refs:[{path,label}]`（path 相對專案 refBase、
  正斜線；可加 uuid 對應程式碼 HARE 註解）。refs 是卡片→程式的定位鏈，建卡不帶＝
  下一個 agent 與使用者都要重新探索；不要「先建卡、路徑之後再說」。事後清點缺漏
  用 validate_cards（plan/exec/chip 缺 refs 會被列出）。
- **id 帶 per-run 戳記**：確定性流水號跨次生成會撞號，殘留分頁的合併推送會把
  舊卡覆寫到新板上。
